{# ===== 1. Synology ===== #}
1. Synology (DS215j) — a aplicação

É a fonte da verdade: atletas, km, ranking, patrocinadores, avisos. Fica ligado o tempo todo.

  1. DSM → Central de Pacotes: instalar Web Station, Python 3.9 e Servidor Web Apache/nginx.
  2. Restaurar a aplicação em /volume1/web/movimente-se (zip codigo_*.zip da pasta de backups).
  3. Criar o ambiente virtual e instalar as dependências: 
    cd /volume1/web/movimente-se
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
  4. Restaurar o banco: copiar config_*.db da pasta de backups para instance/movimente_se.db.
  5. Restaurar o cofre instance/secrets.json (chave de assinatura, cookie do Strava, tokens). Sem ele os links públicos já enviados param de abrir e todos os tokens precisam ser gerados de novo.
  6. Web Station → criar o portal Python com wsgi.py.
  7. Cloudflare Tunnel (cloudflared) apontando para o nginx local.
Reinício que funciona de verdade: touch wsgi.py não recarrega nada neste setup — o Web Station gera a própria configuração do uWSGI. O reinício real é: 
sudo systemctl restart pkg-WebStation-python3.9@682bee6b-cafd-4625-91aa-ff28b1f9d888.service
(ou pelo DSM → Web Station). Validação antes de salvar código: ast.parse — py_compile falha no NAS por permissão nos __pycache__.
{# ===== 2. Máquina da automação ===== #}
2. Máquina da automação — WhatsApp

Descartável de propósito: nenhum dado do MoveMentes mora aqui. Trocar de máquina é copiar três coisas: docker-compose.yml, .env e scripts/.

  1. Docker + Docker Compose (no Windows: WSL2 com Debian).
  2. Subir PostgreSQL 16 + WAHA pelo docker-compose.yml.
  3. No .env, apontar MOVIMENTE_API_URL para a aplicação e colar o token gerado em Painel → Automação.
  4. Vincular o WhatsApp de cada cidade — pela tela Sessão do WhatsApp, não pelo painel do WAHA.
Armadilhas já pagas — não repita:
  • WHATSAPP_START_SESSION junto com WAHA_WORKER_RESTART_SESSIONS inicia a sessão duas vezes e o WhatsApp derruba o vínculo. Deixe só o WAHA_WORKER_RESTART_SESSIONS. O auth timeout no log é a assinatura da colisão.
  • WAHA_WORKER_ID precisa ser fixo. Sem ele o WAHA usa o hostname do container, que muda a cada recriação, e a sessão vira órfã (Sessions: 0 mesmo com os dados no banco).
  • A senha do PostgreSQL não pode ter @: o WAHA lê a senha dentro de uma URL e não decodifica %40. E não teste por 127.0.0.1 de dentro do container — o pg_hba.conf tem trust e aceita qualquer senha (falso positivo).
  • Exited (143) não é crash: é parada intencional (SIGTERM). E restart: unless-stopped não traz de volta o que foi parado de propósito.
  • status: WORKING não quer dizer pronto. Só trabalhe com status=WORKING e engine.state=CONNECTED. Arranque a frio leva 60–90 s.
  • Nunca copie a sessão do WhatsApp entre máquinas: a mesma credencial em dois lugares faz o WhatsApp derrubar o vínculo.
{# ===== 3. Windows ===== #}
3. Windows — agendamento e acesso
  • Atalho manter_wsl_vivo.vbs em shell:startup. Sem ele o WSL encerra a distro sozinho, o Chromium morre e nada interativo funciona (o QR nem chega a existir).
  • Gatilho de logon no Agendador de Tarefas exige elevação — para tarefa de usuário, use atalho em shell:startup.
  • Chamar wsl a partir de um disco de rede (Z:) dá Failed to translate. Rode cd C:\ antes.
  • networkingMode=mirrored exige Windows 11 22H2+; no Windows 10 é ignorado em silêncio. Use netsh portproxy, refeito a cada boot porque o IP do WSL muda.
{# ===== Regra de ouro ===== #}
A regra que não se quebra: nunca escreva no banco por fora da aplicação. O SQLite fica em disco de rede e a aplicação o mantém aberto em WAL — escrever por SMB a partir do Windows falha com disk I/O error e, pior, derruba com erro 500 quem estiver usando o site naquele momento. Toda escrita em massa vira rota administrativa aqui dentro.
