Comandos do Sistema — Admin Master

Voltar
Só o dono da instalação vê esta página. Os comandos mexem no servidor inteiro. Nenhuma senha ou chave aparece aqui — quando um comando precisar de uma, ele a lê sozinho do .env da máquina.
Onde cada coisa roda. Comandos que começam com powershell ou wsl são do computador da automação (o Dell) — abra o PowerShell lá. Os que começam com tail, curl ou sudo são do servidor do site (o Synology) — entre por SSH.
{# ==================================================== #}
1. Primeiro socorro — comece por aqui
{# ==================================================== #}
powershell -ExecutionPolicy Bypass -File "C:\Users\USUARIO\Documents\SCRIPTS\MOVIMENTE\MoveMentes_Conferir_Tudo.ps1"

Confere de uma vez: sintaxe de todos os scripts, privilégio e limite de tempo de cada tarefa do Agendador, a parada limpa do desligamento, a ponte de rede e os scripts Python do WSL. Não liga o WSL só para conferir — cada arranque é uma chance de perder a sessão.

powershell -ExecutionPolicy Bypass -File "C:\Users\USUARIO\Documents\SCRIPTS\MOVIMENTE\MoveMentes_Conferir_Tudo.ps1" -Corrigir

Pede elevação sozinho. Ajusta privilégio das tarefas, limites de tempo, o script da política de desligamento e a ponte de rede.

wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && ./.venv/bin/python scripts/prontidao.py"

Etapa por etapa: container → API → saúde → sessão WORKING + CONNECTED → cópia gravada → o grupo responde à leitura. A última é a única que pega o caso em que o status mente: sessão WORKING com o navegador morto por trás, que devolve HTTP 500 ao ler o grupo.

{# ==================================================== #}
2. A sessão do WhatsApp
{# ==================================================== #}
Nunca reinicie uma sessão em FAILED. Nesse estado o WhatsApp já desvinculou o aparelho do lado dele: reiniciar não traz de volta e ainda pede para apagar a cópia — que é justamente o que permitiria repor sem o celular. Foi o que aconteceu em 19/08 às 19:50.
wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && ./.venv/bin/python scripts/wahasessao.py"

Responde nome|status|estado|quantas. Só vale WORKING com CONNECTED. SCAN_QR_CODE = precisa parear. FAILED = o WhatsApp desvinculou. Este é o único lugar que decide qual sessão usar — sempre pelo estado, nunca pelo nome.

wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && ./.venv/bin/python scripts/copia_sessao.py --conferir principal-pls"

Sem cópia gravada, a sessão não sobrevive a um reinício. Ela é regravada sozinha a cada 2 minutos enquanto a sessão está conectada.

wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && ./.venv/bin/python scripts/copia_sessao.py --repor principal-pls"

Use quando a cópia do banco tiver sido apagada ou corrompida. Ele pega o zip mais recente de copias-sessao/, põe de volta no Postgres e confere que o conteúdo lê. Só peça o celular se isto falhar.

wsl -d Debian -- bash -c "docker logs auto-waha-principal-pls 2>&1 | grep -iE 'logged out|Unpairing|PAIRING|deleteRemoteSession|authenticated' | tail -20"

Leia o reqId de cada logged out: sem reqId quer dizer que o próprio WhatsApp derrubou o aparelho — não foi nada nosso. Com reqId quer dizer que alguém chamou a API (um restart, um logout, o botão Limpar). O estado PAIRING no arranque é o WhatsApp exigindo pareamento novo.

wsl -d Debian -u USUARIO -- bash /home/USUARIO/movimente-automacao/scripts/conectar_whatsapp.sh

Prefira o botão Conectar na tela de Sessão do WhatsApp: ele acorda a máquina, confere disco, Docker e ponte de rede, repõe a cópia se der, e manda o código para o celular e para o e-mail.

{# ==================================================== #}
3. A máquina da automação
{# ==================================================== #}
Nunca desligue o Dell no botão e nunca use docker kill ou wsl --terminate fora da parada limpa. Queda seca do navegador é lida como logout pelo WhatsApp, e depois de algumas vezes ele revoga o vínculo. Um desligamento inesperado em 18/08 também corrompeu o disco do WSL e deixou a automação dois dias fora do ar.
wsl -d Debian -- bash -c "touch /home/USUARIO/.t 2>&1 && rm -f /home/USUARIO/.t && echo 'escrita OK'; df -h / | tail -1; dmesg 2>/dev/null | grep -ciE 'EXT4-fs error|Remounting filesystem read-only'"

Espera-se escrita OK, um disco de ~98 GB e 0 erros. Se der Read-only file system, o disco corrompeu: o Docker não sobe e nada mais adianta até reparar.

wsl -d Debian -- docker ps -a --format "{{ '{{' }}.Names{{ '}}' }} | {{ '{{' }}.Status{{ '}}' }}"

São quatro: auto-postgres, auto-waha-principal-pls, auto-waha-suplente-pls. Atenção a Restarting: o container aparece na lista igualzinho a um saudável, mas está morrendo e ressuscitando em laço.

powershell -Command "Get-ScheduledTask | Where-Object { $_.TaskName -like '*ovimente*' } | ForEach-Object { $i = $_ | Get-ScheduledTaskInfo; [PSCustomObject]@{ Tarefa=$_.TaskName; Nivel=$_.Principal.RunLevel; Ultima=$i.LastRunTime; Resultado=$i.LastTaskResult; Proxima=$i.NextRunTime } } | Format-Table -AutoSize"

Resultado 0 = terminou bem. 267009 = ainda rodando. 267014 = foi morta pelo Agendador por estourar o limite de tempo — some do log sem desfecho. Nivel tem de ser Highest, senão a ponte de rede nunca é refeita.

powershell -ExecutionPolicy Bypass -File "C:\Users\USUARIO\Documents\SCRIPTS\MOVIMENTE\MoveMentes_Instalar_ParadaLimpa.ps1"

Roda uma vez. O script de desligamento do Windows roda como SYSTEM, e SYSTEM não enxerga o WSL (a distro é registrada por usuário) — por isso ele chama uma tarefa que roda como você e espera ela fechar tudo. Confira depois em logs\pararlimpo_AAAAMMDD.log.

powershell -Command "Start-ScheduledTask -TaskName 'MoveMentes - Parada limpa'"

Confere a cópia da sessão, para os containers um a um e encerra o WSL. É o caminho seguro para mexer na máquina.

netsh interface portproxy show all & wsl -d Debian -- hostname -I

O IP interno do WSL muda a cada arranque. Quando a ponte fica apontando para o endereço velho, o site perde o WhatsApp em silêncio: nada dá erro, só para de funcionar. O Conferir Tudo -Corrigir refaz.

{# ==================================================== #}
4. O ranking
{# ==================================================== #}
wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && MOVIMENTE_FORCAR=1 bash scripts/executar.sh --dry-run"

MOVIMENTE_FORCAR=1 fura a janela de horário (05:10–06:15 e 15:10–16:15). Sem ele, fora da janela o script responde "nada a fazer" e sai — que é o mesmo que o botão Publicar agora do painel usa por dentro.

wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && MOVIMENTE_FORCAR=1 bash scripts/executar.sh"

Antes de rodar, confira no painel se o modo teste está como você quer: ligado manda tudo para o seu número; desligado manda para o grupo, e publicar no grupo não tem volta.

wsl -d Debian -- bash -c "tail -60 $(ls -t /home/USUARIO/movimente-automacao/logs/send_ranking_*.log | head -1)"

Procure PIPELINE CONCLUIDA (deu certo), RODADA INTERROMPIDA (parou e por quê), e entregue (ack 2), que é a prova de que a mensagem chegou ao aparelho — enviado não é o mesmo que entregue.

wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && ./.venv/bin/python scripts/send_ranking.py --laudo"

É o que a máquina roda antes de desligar. Se disser que não vai acontecer, ainda dá tempo de agir.

5. O site (Synology)
{# ==================================================== #}
ssh -o ProxyCommand='cloudflared access ssh --hostname {{ ssh_hostname }}' {{ ssh_user }}@{{ ssh_hostname }}
curl -s -o /dev/null -w "HTTP %{{ '{' }}http_code{{ '}' }} em %{{ '{' }}time_total{{ '}' }}s\n" -m 30 {{ base_url_do_site }}/
tail -200 /volume1/web/movimente-se/logs/movimente_se.log | grep -iE "ERROR|WARNING"
tail -f /volume1/web/movimente-se/logs/movimente_se.log
head -2 /volume1/web/movimente-se/wsgi_debug.txt; date

O horário do arranque tem de ser mais novo que o da alteração. Salvar um .py não aplica sozinho: o recarregamento só reage ao wsgi.py mudar de data. Página .html recarrega sozinha.

free -m; uptime

O Synology tem 512 MB. É por isso que o WhatsApp roda no Dell e não aqui: cada sessão come de 400 a 700 MB.

{# ==================================================== #}
6. Banco e backup
{# ==================================================== #}
Nunca abra o banco do site pelo Z: — nem para ler, nem com mode=ro. O SQLite grava o índice mesmo só lendo, e pela rede isso derruba o site com disk I/O error. Para ler, use uma cópia feita pelo próprio site.
wsl -d Debian -u USUARIO -- bash -lc "cd /home/USUARIO/movimente-automacao && docker exec auto-postgres pg_dumpall -U automation > backups/dump_$(date +%Y%m%d).sql"
wsl -d Debian -- ls -lh /home/USUARIO/movimente-automacao/copias-sessao/

É a rede de segurança: guarda as 3 cópias mais recentes de cada sessão. É daqui que o --repor tira o zip quando o banco perde a cópia.
